# Shared single-product command

The dispatcher command `digitalogic_recalculate_product_price` accepts `product_code` and calls the existing pricing coordinator used by REST and CLI. It requires manage_woocommerce in addition to dispatcher access. No second calculator or relaxed machine principal is introduced.

Single operations invalidate cached authority, write mode and source state after acquiring pricing/source locks. On2026-09-08 the coordinator was deployed and tested in one real PHP process: before each of two calls, only that process's Redis drop-in local cache was seeded with authority go, invalid mode and empty source state. The stale reads were confirmed before invoking the operation. Both calls recovered authoritative PHP/direct_db, one real source, already-current1, pending0 in124ms and142ms. Database settings were not changed. This proves these local-cache recovery boundaries, not changed-product calculation or WebSocket E2E.

The coordinator and dispatcher files are installed. An in-process dispatcher check rejected an anonymous request with digitalogic_unauthorized and completed two administrator calls in130ms and133ms, each with PHP authority, one source, already-current1 and pending0.

After restarting the existing WebSocket service, real loopback WebSocket acceptance completed two commands on one connection in134ms and148ms (coordinator132ms and137ms), PHP authority, already-current1, pending0. A separate ping-only probe succeeded before command execution. The first connection probe had failed without a classified cause; subsequent success does not prove why. Temporary client tokens were revoked. No new PHP process/service was added. Desktop-network latency, changed-input product-cache freshness and changed-price latency remain unverified. Do not extrapolate loopback unchanged results into complete E2E acceptance.

Windows public WSS acceptance subsequently completed two commands on one connection in107ms/113ms. A separate run measured handshake71ms followed by commands104ms/112ms: approximately175ms from connection attempt through first command response, excluding prior credential issuance. Each response reported PHP, already-current1 and pending0. Temporary authenticated client tokens were revoked; all three services remained active. This proves the public transport for unchanged committed inputs, not changed-price latency or current desktop application integration. The installed single CLI still uses HTTPS REST; it has not silently switched transports. Changed-input/cache validation remains open.
